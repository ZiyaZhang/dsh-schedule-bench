# dsh-schedule-bench

Benchmark for scheduled tasks in [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness): it runs the same four tasks against two DSH checkouts and compares correctness, delivery delay, model cost and Host load. The first use compares the schedule runtime before and after wake-up moved into a clock source provider; the design and regression rules are in [PLAN.md](PLAN.md).

## Tasks

| Task | What it checks | Model |
| --- | --- | --- |
| 1 Every-minute check-ins | about 100 deliveries from one-shot, 60-second and cron tasks: none missed or repeated, delivery delay | fake |
| 2 Three tasks due together | three tasks in one Session due in the same minute: files right, turns, tokens, time to done | real |
| 3 100 tasks due in one second | burst delivery with 100 and 1,000 active tasks: last delivery, CPU, event-loop stalls | fake |
| 4 Missed while stopped, failed open | catch-up delivers the latest missed occurrence once; a delivery whose Session fails to open is retried | fake |

## Layout

- `bench/sched-bench.e2e.ts` — the scenarios. The runner copies it into `apps/web/tests/` of each checkout and runs it with the checkout's own `vitest.web.config.ts`, so it boots the shipped Web composition through the repository's e2e scaffold.
- `tasks/t2-morning/` — task 2 files, prompts and answer key, generated by `scripts/make-t2-fixtures.mjs`.
- `scripts/run.sh` — runs tasks one at a time in the planned order.
- `scripts/summarize.mjs` — writes `results/<run>/summary.md` from the result files.
- `results/<run>/` — one JSON file per task and version, run logs, and the summary.

## Run

```bash
# two built checkouts: pnpm install --frozen-lockfile && pnpm run build:artifacts (Node 24)
export BENCH_OLD=/path/to/old-checkout BENCH_NEW=/path/to/new-checkout
export BENCH_ENV_FILE=/path/to/.env   # DEEPSEEK_API_KEY for task 2; never committed
scripts/run.sh my-run                 # all eight runs, about 40 minutes
node scripts/summarize.mjs my-run
```

`BENCH_BASE_URL` overrides the model endpoint for task 2, `BENCH_SAMPLES` sets its sample count (default 5), and `BENCH_NODE_BIN` points at a Node 24 toolchain.
